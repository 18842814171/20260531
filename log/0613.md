# Development log — 2026-06-13

## Summary

Migrated myos user-process scheduling toward **xv6-style per-process kernel contexts** (`proc_kctx_switch`). Completed **Stage 1** (storage) and **Stage 2** (block → sched → scheduler stack). Fixed **interactive shell typing freeze** caused by the shell never being resumed after UART `proc_block`. Removed **`proc_user_run_resume`**; blocked syscalls now unwind through the existing stack after `proc_kctx_switch` back, not a second `enter_uspace`.

**Stage 3** (READY → `switch_to(kctx)` for first dispatch) and **Stage 4** (delete coroutine machinery) are **not** done.

---

## Motivation

Prior model mixed two worlds:

- **Kernel demo scheduler** (`proc/sched.c` → `switch_to`) — full trap-frame switch
- **User programs** — C coroutine (`proc_user_run`, `after_uspace`, `run_saved_cont`, `depth`)

Blocking nested `proc_sched_run_ready()` on the blocked process’s live C stack frame caused:

1. **`ipc_echo quit` panic** — stale `after_uspace` / wrong `saved_pid` when nested scheduling captured the blocked producer instead of ipc_echo parent
2. **Typing freeze** — over-correction filtering `depth>0` from dispatch, or (after Stage 2) shell never resumed because resume required `depth>0` + pagetable

**Target invariant (xv6):** a blocked process owns its continuation; wakeup resumes it; the scheduler never creates a second user entry path.

Reference tree: `xv6-riscv-riscv` — `sleep → sched → swtch`, no `depth`, no continuation labels.

|------|----------|

### Trap frame

- `interrupt/entry.S` — hardcoded offset `0x11a0` for `user_ctx` lookup from kstack top

**Behavior:** unchanged at runtime; coroutine path still authoritative.

## Stage 2 — `proc_block` → `proc_sched` → scheduler

### Added

| Item | Location |
|------|----------|
| `proc_kctx_switch(old, new)` | `interrupt/kctx_switch.S` — xv6-style save/restore, `ret` |
| `sched_stack[4096]`, `sched_kctx` | `proc/proc_sched.c` |
| `proc_scheduler_loop()` | Runs on scheduler stack: dispatch fresh READY, resume sleepers, `wfi` |
| `proc_sched()` | Save to `p->kctx`, switch to scheduler; returns when resumed |
| `proc_pick_next_ready_resume()` | Pick READY processes sleeping in `proc_sched` |

### Changed

**`proc_block`** — no longer calls `proc_sched_run_ready()` inline on caller stack:

```text
proc_block → proc_sched() → proc_kctx_switch(proc, sched)
scheduler loop → … → proc_kctx_switch(sched, proc) → return in proc_block
```

**`proc_pick_next_ready`** — skips `kctx_asleep` and `depth>0` (still dispatch-only for fresh user procs).

## Interactive shell fix — `kctx_asleep`

### Problem

After Stage 2, **keyboard input at `login:` / shell prompt had no effect**.

Shell (pid 1) blocks via `uart_readc_wait` → `proc_block` → `proc_sched`. On UART IRQ wakeup:

- Shell is **READY**, `depth == 0`, **no pagetable**
- Old resume picker required **`depth > 0` AND pagetable** → shell never resumed → permanent `wfi`

### Fix

| Item | Details |
|------|---------|
| `procs[].kctx_asleep` | Set `1` in `proc_sched()` before switch; cleared on return |
| `proc_pick_next_ready_resume()` | `READY && kctx_asleep && kctx.ra != 0` (no depth/pagetable gate) |
| `proc_pick_next_ready()` | Skip `kctx_asleep` so sleepers are not double-dispatched |

**Note:** Interactive shell does **not** require Stage 3. Shell runs in kernel context via `console_run()`, not `proc_user_run_dispatch`.

**Operator:** use `DEBUG=n ./sh/start_qemu.sh` on a real terminal (`DEBUG=y` pipes stdout to osviz and steals keyboard).

## Mental model (post–Stage 2)

```text
Good:  BLOCKED → proc_sched → scheduler → wakeup → kctx resume → syscall returns → user
Bad:   READY + active continuation → proc_user_run() again (second continuation)
Bad:   proc_sched_run_ready() nested on blocked process C stack frame
```

Shell UART wait uses the **same** `proc_sched` / `kctx_asleep` path as user `sem_wait` / `read(0)`.
