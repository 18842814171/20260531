# 0616 调试与功能变更记录

本文记录 6 月 16 日批量测试管线、控制台输出分级、事件面板顺序与 PMM 降噪、脚本默认行为等改动。叙述采用书面语；涉及模块名、文件名处为便于对照保留原文。

---

## 一、背景与目标

在网页终端与观测分流（见 `log/0615debug.md`）已稳定的基础上，本轮重点解决三类问题：批跑时串口被启动信息与进程跟踪淹没；Web 事件气泡在 trap 突发时乱序入场；高频物理页分配事件挤占右侧面板。同时建立可在本机重复执行的 guest 批量测试流程，不依赖 oscomp 预置镜像。

---

## 二、控制台输出分级（与 LOG 分离）

### 2.1 设计

内核存在两类面向人类的串口输出：

| 类别 | 宏 | 典型内容 | 与 Web 气泡关系 |
|------|-----|----------|-----------------|
| 结构化观测 | `LOG_*` | JSON 行，供 demux | 是 |
| 启动与进程跟踪 | `boot_printf` / `proc_printf` | HEAP、trap_init、ENTER/LEAVE、[exit] 等 | 否，进终端 |

二者均经 `printf` → `console_*` → UART，但开关独立。

### 2.2 编译规则（`include/config.h`）

| 条件 | `CONSOLE_BOOT` | `CONSOLE_PROC` |
|------|----------------|----------------|
| `make DEBUG=0` | 关 | 关 |
| `make AUTORUN=…` | 关 | 关 |
| `make DEBUG=1` 且无 AUTORUN | 开 | 开 |

`LOG_*` 仍仅由 `DEBUG` / `CONFIG_LOG` 控制；批跑可用 `make AUTORUN=test DEBUG=0` 同时关闭两类输出。

### 2.3 调用点迁移

| 文件 | 改动 |
|------|------|
| `interrupt/trap.c` | `trap_init` 信息 → `boot_printf` |
| `interrupt/timer.c` | 定时器调试行 → `boot_printf` |
| `mem/pmm.c`、`mem/default_pmm.c` | 堆与自检 → `boot_printf` |
| `mem/vm.c` | Sv39 启用行 → `boot_printf` |
| `proc/proc_user.c` | ENTER/LEAVE、[exit] → `proc_printf` |
| `proc/proc.c` | destroy vm、[zombie] → `proc_printf` |
| `boot/kernel.c` | AUTORUN 路径跳过 `Hello, RVOS!` 等欢迎语 |

## 三、批量测试管线

### 3.1 组成

| 组件 | 路径 | 作用 |
|------|------|------|
| 驱动程序 | `home/root/test.c` | 读 `testcases.list`，逐条 fork/exec/wait |
| 用例表 | `home/root/testcases.list` | 稳定用例名；`!` 前缀表示跳过 |
| 宿主脚本 | `sh/run_batch.sh` | 启动 QEMU、写 `out/batch.log`、调用判题 |
| 判题 | `tests/judge_batch.py` | 解析 `BATCH_SUMMARY` 与 START/END 块 |

新增稳定用例源文件（经 `./usr/compile.sh c` 编译后打入 ramfs）：`getpid_test.c`、`fork_wait.c`、`file_create.c`、`yield_once.c`、`sem_test.c`、`write_test.c` 等。

### 3.2 输出约定

每个用例打印：

```text
========== START <name> ==========
…
exit status=<n>
========== END <name> ==========
```

结束时汇总：

```text
BATCH_SUMMARY pass=… fail=… skip=… total=…
autorun: done status=0
```

### 3.3 推荐用法

```bash
cd code/myos
make AUTORUN=test DEBUG=0
./sh/run_batch.sh
```

`run_batch.sh` **不再自动 make**；切换 AUTORUN 后若行为未变，需 `rm -f out/boot/kernel.o && make …` 强制重编内核对象。

### 3.4 与 oscomp 套件的关系

仓库外 `testsuits-for-oskernel-pre-2025` 依赖 ext4、musl 与完整 Linux  syscall，当前 LibertyOS 无法直接接入。本地批量表针对 ramfs 与现有 syscall 子集，用于回归与答辩演示。

## 四、脚本默认行为

### 4.1 `sh/start_qemu.sh`

| 变量 | 默认 | 说明 |
|------|------|------|
| `DEBUG` | `n` | 串口直连终端；Web 由 `server.py` demux |
| `MYOS_QUIET` | `0` | 为 `1` 时不打印 QEMU 横幅（批跑用） |

`DEBUG=y` 仅用于可选离线写入 `events.jsonl`，与网页气泡无关。

### 4.2 `sh/run_batch.sh`

设置 `MYOS_QUIET=1 DEBUG=n`，经 `timeout` 跑 QEMU，管道输出至 `out/batch.log`，再执行 `judge_batch.py`。

## 五、网页事件面板（6.16）

### 5.1 串行入场

原先每条气泡独立随机延迟 100–500ms，trap 突发时后到的可能先显示。现改为串行队列：上一条 CSS 过渡结束后再挂载下一条；间隔 `REVEAL_GAP_MS`（50ms），`REVEAL_FALLBACK_MS`（100ms）防止队列卡死。

### 5.2 PMM 降噪

| 层级 | 行为 |
|------|------|
| 前端 `QUIET_MODULES` | `module=pmm` 不进入右侧主面板（串口与 jsonl 仍可有） |
| 内核 `mem/pmm.c` | 去掉每次 alloc/free 的 `LOG_PMM`；保留 init 与 alloc_fail |

修改文件：`code/web/js/logs.js`、`code/myos/mem/pmm.c`。

## 六、缺陷修复

### 6.1 `test.c` 读列表死循环

**现象：** 批跑在 `exec_hi` 附近挂起，无 `BATCH_SUMMARY`。

**原因：** `read_line` 在 EOF 时若栈上残留 `c == '\n'`，会反复读空行。

**修复：** EOF 且无已读字节时返回 `-1`；进入循环前 `c = 0`。

### 6.2 AUTORUN 切换不生效

**现象：** 修改 `make AUTORUN=…` 后仍跑旧程序。

**原因：** `kernel.o` 未因 AUTORUN 宏变化而重编。

**处理：** 切换 AUTORUN 时删除 `out/boot/kernel.o` 后全量 make。

---

## 七、关于在用户程序中 `#define DEBUG`

在 `test.c` 内定义 `DEBUG` **不能**关闭内核的 `boot_printf`、`proc_printf` 或 `LOG_*`。用户 ELF 与内核分开编译；调试开关在内核 `config.h` 与 Makefile 的 `-DDEBUG`、`-DCONFIG_AUTORUN` 中生效。若需「同一份内核、仅跑 test 时安静」，须增加运行时 syscall 或按程序名切换，属后续可选工作。
