# 0621 调试与功能变更记录

本文记录 6 月 21 日网页日志分层、内核结构化观测、串口分流与终端显示等改动。叙述采用书面语；涉及路径、命令处为便于对照保留原文。

---

## 一、背景与目标

此前右侧事件面板为扁平气泡列表，难以对应「一次命令」的完整过程；观测数据依赖程序名列表与文本正则，与「内核发结构化记录、主机按通道分流」的原则不符。本轮目标：

1. 建立 **命令 → 语义事件 → 原始记录** 三级展示；
2. 进程生命周期、缺页等改由内核 **结构化记录** 输出，前端按模块与事件名归类；
3. 消除终端中观测 JSON 泄漏、输出与提示符粘连、提示符不同步等问题。

---

## 二、内核：结构化进程与缺页记录

### 2.1 进程生命周期

原先通过 `proc_printf` 输出纯文本（如进入用户态、退出、僵尸、销毁页表等），网页端只能对文本做正则匹配。

**现改为** `LOG_PROC` 结构化事件，主要包括：

| 事件名 | 含义 |
|--------|------|
| user_enter | 用户态首次运行 |
| user_exit | 正常或异常退出 |
| exit_trap | 退出陷阱返回路径 |
| zombie | 进程变为僵尸 |
| vm_destroy | 销毁页表 |
| trap_return | 自用户态陷阱返回调度 |

头文件新增 `LOG_APP` 宏，供后续应用里程碑（如编辑器保存、进程间通信结束）使用。

### 2.2 缺页记录

`./pagefault` 演示程序的缺页均由内核按需映射处理，原先**不**产生观测记录，面板只能看到进程生命周期。

**现改为**：映射成功时发送 `LOG_IRQ("page_fault", …, handled=1)`；无法处理时发送 `handled=0` 并进入原有异常路径。

### 2.3 输出格式与缓冲区

- 迷你打印实现不支持 `%u`，观测数据统一改用 `%d`、`%lx` 等已支持格式；
- 缺页记录 JSON 约 87 字节，原 64 字节缓冲区导致截断、主机解析失败后丢弃——已扩至 128 字节；
- 删除与结构化记录重复的 `printf`（如用户态致命缺页提示），避免终端重复显示。

### 2.4 串口写入原子性

控制台与观测共用一条串口，并发写入会导致字节交错（终端出现 `odule":"sched"` 等碎片）。

**现改为**：`console_write` 与 `log_write` 在关中断期间整段发送；`proc_trace_printf` 合并为单次写入。

## 三、网页前端：三级日志面板

### 3.1 新增文件

| 文件 | 作用 |
|------|------|
| `js/log_aggregate.js` | 归类规则：按内核 module/event 分桶，不依赖程序名列表 |
| `js/logs_tree.js` | 三级界面：命令卡片 → 语义事件 → 原始 JSON |

`desktop.html` 默认加载上述脚本；`logs.js` 仍作扁平列表后备。

### 3.2 归类原则

| 层级 | 含义 | 示例 |
|------|------|------|
| 一级 | 一次用户命令或进程组 | `./pagefault pid=3` |
| 二级 | 语义行为（有内容才显示） | 缺页、进程生命周期、信号量 |
| 三级 | 单条观测 JSON 或附注 | pid、stval、handled |

- 内置命令（pwd、ls 等）一级显示「已完成」，通常无二级；
- 外部程序（`./` 开头）按实际观测桶显示二级；
- 缺页二级优先于进程生命周期排列。

### 3.3 命令边界

一级在以下情况关闭：进程退出、显式结束（如进程间通信完成）、提示符出现（兜底）。提示符**不等同**于进程结束；锚点进程退出后仍等待提示符再关闭，以收齐尾部记录。

## 四、主机分流与终端

### 4.1 SerialDemux

- 观测 JSON 解析失败时**不再**回退到终端（避免污染 shell 输出）；
- 丢弃无 `LOG ` 前缀的 JSON 碎片（防御性，应对历史交错残留）。

### 4.2 终端显示

| 问题 | 原因 | 处理 |
|------|------|------|
| `pagefault: done.` 与提示符同一行 | `write` 长度少 1，未输出换行 | 修正 `pagefault.c`；shell 打印提示符前补换行 |
| `cd` 后输入栏仍显示旧目录 | `#console-prompt` 写死为 `/home/root` | 从 guest 提示符行同步更新 |
| 占位符与终端文案不一致 | `desktop.js` 与 `terminal.js` 各设一套 | 统一由 `terminal.js` 管理占位符 |

## 五、验证建议

```text
1. code/myos 下 make；重启 code/web/start_server.sh；浏览器硬刷新

2. ./pagefault
   - 终端：两行程序输出 + 独立一行提示符
   - 面板：一级 ./pagefault；二级「N page faults」+「process lifecycle」

3. ./segfault_null
   - 终端：仅 before fault，无内核 killed 字样
   - 面板：fault_kill、user_exit 等

4. ./ipc_echo
   - 终端：生产者/消费者交互文字（程序自带输出）
   - 终端无 JSON 碎片；面板有 sem/proc/sched 记录

5. cd dir1
   - 滚动区与输入栏左侧提示符均为 root@/home/root/dir1$
```

## 六、仍不稳定或未完成项

| 项 | 说明 |
|----|------|
| 单串口架构 | guest 仍共用一个 UART；关中断整段发送可缓解交错，多核或高并发下仍需独立观测通道（规划中的第三步） |
| 应用调试输出 | ipc_echo、sem_test 等仍用 `printf` 打终端；结束边界靠终端匹配「ipc_echo done」文本，应逐步改为 `LOG_APP` |
| 生命周期二级过详 | `./pagefault` 时 trap_return 等仍归入 lifecycle，信息偏多；待 activity 分组或按命令故事折叠 |
| 提示符双重显示 | guest 在滚动区打印提示符，输入栏左侧另有标签，属当前布局，易误解为目录回退 |
| 其他 write 长度 | 部分测试程序 `write` 第三参数与字符串长度不一致（如 hi.c），可能导致粘连，需逐项核对 |
| 解析失败静默丢弃 | 主机对坏 JSON 不报错、不入面板，排查需抓串口原文 |
| 未接入的草稿 | `logs_session.js`、`terminal_session.js` 在仓库中但未加载 |
| 后台任务 | 带 `&` 的命令一级边界未按作业表实现 |
| 观测附注 | `LOG_NOTE` 仅用于缺页情境栈；进程生命周期已不再依赖附注文本 |
